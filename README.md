# Дурак Онлайн

Многопользовательский дурак в браузере: лобби с кодом приглашения, живые ходы,
проверка правил на сервере и единая тёмная тема.

## Запуск

Для раздельного развёртывания статики и Rust backend без Node в production см.
[инструкцию и пример nginx](docs/DEPLOYMENT.md).

Для основного запуска используйте Rust-сервер из корня проекта. Игроки входят
по имени и паролю клубного аккаунта. Node.js для запуска не нужен:

```bash
cargo run --manifest-path rust/Cargo.toml -p platform-server --locked
```

Команда `npm start` доступна как сокращение для разработки.

Он слушает `http://localhost:4173`, отдаёт существующий браузерный клиент,
совместимый HTTP/SSE API и сохраняет служебную SQLite-схему в
`data/durak.sqlite`. Путь к базе меняется через `DURAK_DB`, адрес через `HOST` и
`PORT`. Проверка готовности доступна по `/readyz`.

Если сохранённая идущая партия содержит не покинувшего её игрока без привязки
к Discord или действующего клубного аккаунта, Rust-сервер прерывает запуск
с ошибкой, указывающей комнату и игрока.
Автоматической отмены партии и возврата ставок при этом нет. Администратору нужно
осторожно разрешить миграцию или отмену комнаты до повторного запуска, сохранив
резервную копию базы и проверив последствия для ставок и балансов. Готовый
автоматический способ возврата для этого случая не предусмотрен; подробности — в
[документации хранилища](docs/BACKEND_PERSISTENCE.md).

Для включения панели администратора задайте собственный `ADMIN_KEY`.

Откройте http://localhost:4173. Чтобы позвать друга, создайте лобби и отправьте
ему ссылку вида `http://localhost:4173/?code=XXXXXX` или сам код.

Backend и MCP реализованы на Rust. JavaScript в рабочем серверном контуре используется только браузером.

Друзья из локальной сети открывают игру по адресу вашей машины, например
`http://192.168.0.20:4173` (порт 4173 должен быть открыт в файрволе). Для входа
через Discord нужен HTTPS; HTTP разрешён только для loopback-адресов.

## Что умеет

- Лобби на 2–6 игроков, вход по коду, список открытых игр и счётчик онлайна в
  реальном времени (Server-Sent Events).
- Режимы: подкидной и переводной (тот же подкидной плюс право перевести ход);
  колода 36 или 52 карты.
- Сервер сам следит за правилами: очередь хода, козырь, старшинство карт,
  подкидывание по достоинствам карт на столе всеми активными игроками кроме
  защитника, лимит шесть атак и ограничение по руке защитника, перевод хода,
  взятие карт, добор до шести, выход игроков и определение дурака.
- Профиль с именем, цветом аватара, балансом и статистикой партий; фиксированная
  тёмная тема.
- Ставки: за столом можно указать фишки (50–500). Каждый игрок вносит ставку
  при старте, дурак теряет свою, банк делят остальные.
- Панель клуба для администратора на отдельной странице `/admin`: список игроков,
  создание клубных учёток с паролем, смена пароля, правка имени, баланса и
  статистики, удаление учёток. Пароли хранятся только в виде соли и хеша
  PBKDF2-SHA256 (600 000 итераций), смена пароля закрывает открытые сессии.
  Ключ доступа задаётся через `ADMIN_KEY`; без него панель отключена.
- Перезапуск партии создателем лобби. Первый ход получает владелец младшего
  козыря; добор начинается с исходного атакующего, защитник добирает последним.
- При переводе игрок выбирает карту; перевод разрешён только до первого покрытия
  и при достаточном числе карт у следующего защитника.
- Выход активного игрока завершает партию его поражением. Отключение сохраняет
  место; если все отключены пять минут, партия отменяется с возвратом ставок.
- Каждая вкладка хранит секрет сессии. Знание публичного идентификатора игрока
  не даёт доступа к его картам или действиям. Для недоверенных сетей нужен HTTPS.

## Проверки

Текущие JS helper и интеграционные тесты используют Rust backend и Rust MCP; `TEST_BACKEND`
можно не задавать или задать `rust`. Команда тестов требует заранее запущенный Rust
сервер и не является подтверждением пройденного интеграционного прогона:

```bash
TEST_BACKEND=rust ADMIN_KEY=test-only-secret BASE_URL=http://127.0.0.1:4175 npm test
```

Rust workspace проверяется из каталога `rust`:

```bash
cargo build -p platform-server --locked
DURAK_SERVER_BIN="$PWD/target/debug/platform-server" cargo test -p platform-mcp --test service --locked
DURAK_SERVER_BIN="$PWD/target/debug/platform-server" cargo test --workspace --locked
cargo fmt --all -- --check
cargo clippy --workspace --all-targets -- -D warnings
```

Для black-box проверок против Rust-сервера сначала запустите его на другом порту:

```bash
ADMIN_KEY=test-only-secret HOST=127.0.0.1 PORT=4175 DURAK_DB=/tmp/durak-test.sqlite cargo run -p platform-server
```

Для запуска интеграционного набора используйте `TEST_BACKEND=rust ADMIN_KEY=test-only-secret BASE_URL=http://127.0.0.1:4175 npm test` из корня проекта после запуска сервера. Набор и MCP helper используют только Rust backend/MCP. Временная база нужна для Rust backend. Интеграционный прогон в этой документации не считается проверенным. Тесты сами создают временные клубные аккаунты через `/api/admin`, используют их для сценариев и выполняют cleanup созданных данных.

Детерминированные проверки движка и клиента запускаются без сервера:

```bash
node tests/client.mjs
```

В состав интеграционного набора входят проверки защиты сессий, переподключения,
входа в другой стол, обоих режимов, выбора карты перевода, лимитов, порядка добора,
выхода игроков, возврата ставок, полной партии и серверных хуков `/api/watch`
(журнал действий, ожидание своего хода и конца партии). Это описание состава набора,
а не утверждение, что прогон уже прошёл. Для изолированного сервера на другом порту
укажите `BASE_URL` при запуске `npm test`.

## MCP-сервер

`platform-mcp` — основной MCP-сервер Rust (stdio) поверх HTTP API игры. Он
запускается командой:

```bash
cargo run --manifest-path rust/Cargo.toml -p platform-mcp --locked
```

Для разработки также доступна команда `npm run mcp`. MCP открывает места игроков через SSE, садится за стол, ходит по правилам и может
прогнать партию ботов целиком. Передайте `clientId` и токен сессии, либо войдите
через `login` и `password`; при наличии ключа администратора можно создать аккаунт
через `create=true`. Подробности — в [README адаптера](rust/crates/platform-mcp/README.md).
В рабочем запуске используются Rust `platform-server` и `platform-mcp`. Ключ панели клуба берётся из
`DURAK_ADMIN_KEY` или `ADMIN_KEY`.

Инструменты:

- `durak_connect`, `durak_disconnect`, `durak_seats` — места игроков и их
  SSE-каналы; без открытого места сервер отклоняет ходы.
- `durak_lobby`, `durak_status` — сведения о лобби и статусе сервиса.
- `durak_room_create`, `durak_room_join`, `durak_room_leave`, `durak_start`.
- `durak_action` — `attack`, `defend`, `transfer`, `take`, `pass` с `cardId` и
  `targetCardId`.
- `durak_state`, `durak_hints` — снимок стола и подсказка легальных карт.
- `durak_turn` — один запрос вместо `state`+`hints`: снимок, легальные ходы, учёт
  вышедших карт и рекомендованный ход с обоснованием. Только читает.
- `durak_wait`, `durak_watch` — ожидание по серверному хуку `/api/watch`:
  `any`, `game`, `your-turn`, `opponent`, `finished`. Ответ приходит, как только
  сработало условие, и содержит журнал действий соперника. `durak_watch` держит
  ожидание до `totalMs` (по умолчанию 180 с), поэтому ход соперника не требует
  сообщения в чате. Серверный журнал ограничен: `/api/watch` возвращает последние
  12 событий, поэтому старый `since` не гарантирует полный replay. Если действие
  случилось раньше вызова, место отдаёт накопленный журнал сразу (`via: "cache"`)
  вместо ожидания таймаута.
- `durak_follow` — играет своим местом до конца партии: сам выбирает
  `defend`/`attack`/`transfer`/`take`/`pass`, между ходами ждёт серверный хук и
  возвращает один краткий отчёт. Ответы инструментов по умолчанию краткие; полный
  снимок стола добавляет `verbose: true`.
- `durak_profile`, `durak_admin` — имя игрока и панель клуба.
- `durak_autoplay` — проверка сервиса целиком: открывает 2–6 мест, играет
  партию простой стратегией и возвращает дурака, шаги и балансы.

Места игроков в Rust MCP переживают перезапуск MCP: метка, `clientId` и токен пишутся в
`DURAK_MCP_SESSIONS` (по умолчанию `~/.local/state/durak-mcp/sessions.json`, права
0600) и восстанавливаются при старте, поэтому партия продолжается между
сообщениями: агент подключается один раз и вызывает `durak_follow`, который сам
доигрывает партию через серверный хук; точечное ожидание одного события даёт
`durak_watch`. Все читающие и игровые `mcp_durak_*` внесены в `permissions allow`
в `.crushrc`, а таймаут вызова поднят до 300 с, чтобы long-poll ожидание не
обрывалось. `durak_admin` и `durak_autoplay` намеренно не разрешены: они меняют
балансы и создают аккаунты, поэтому подтверждаются в чате.

## Вход через Discord

Для Rust-сервера задайте вместе `DISCORD_CLIENT_ID`, `DISCORD_CLIENT_SECRET` и
`DISCORD_REDIRECT_URI`, зарегистрировав точный redirect URI в Discord. Нужен HTTPS;
HTTP допускается только для loopback. Эти настройки нужны для OAuth через
Discord. Вход по имени и паролю клубного аккаунта доступен и без них. Если задана
только часть переменных Discord, сервер прерывает запуск.
Клиент хранит токен приложения в `sessionStorage` вкладки. Старые гостевые записи
сохраняются в базе, но недоступны для входа и автоматически не связываются с
Discord. Выход в личном кабинете очищает сессию вкладки, но не отзывает её на
сервере; cookie-сессии пока нет. Вход необходимо проверить с
реальными учётными данными Discord до развёртывания. Подробности — в
[docs/BACKEND_PERSISTENCE.md](docs/BACKEND_PERSISTENCE.md).

## Вход и личный кабинет

Игроки входят по имени и паролю, который выдаёт администратор клуба (или сам
администратор создаёт временный аккаунт). Сессия живёт в `sessionStorage`
вкладки; выход — в личном кабинете («Кабинет» в навигации или клик по профилю).
В кабинете видны баланс, статистика, последние партии клуба и быстрый доступ к
столу и правке профиля.

## Администратор

Панель клуба вынесена на отдельную страницу `/admin` (файл `admin.html`); в
основном интерфейсе кнопки панели нет. Ключ задаётся при запуске из `rust`:

```bash
ADMIN_KEY=мой-ключ cargo run -p platform-server
```

Если переменная не задана, панель отключена. Ключ хранится только в
`sessionStorage` вкладки. На странице панели можно искать игроков, менять имя,
пароль временного аккаунта, баланс и статистику, сбрасывать прогресс,
пополнять баланс и создавать временные аккаунты. Rust-сервер сохраняет игровые snapshots и изменения
аккаунтов в SQLite и восстанавливает активные комнаты после перезапуска при
прохождении проверок подлинности аккаунтов игроков. SSE,
сессии и ожидающие OAuth-flow остаются в памяти. Rust сохраняет игровые snapshots,
переходы аккаунтов и историю в SQLite.

## Структура и миграция

Rust workspace содержит `durak-engine`, `platform-api`, `platform-server` и
`platform-mcp`. Браузерный клиент остаётся на JavaScript. Rust backend и MCP являются текущим рабочим путём. JavaScript остаётся только в браузерном
клиенте и тестовых helper-скриптах.

Текущее состояние и целевая архитектура описаны в
[docs/ARCHITECTURE.md](docs/ARCHITECTURE.md), оставшиеся этапы — в
[docs/MIGRATION_PLAN.md](docs/MIGRATION_PLAN.md). SQLite открывается при старте, игровые snapshots и изменения аккаунтов
записываются атомарными переходами, а активные комнаты загружаются при старте.
При обычном завершении партии история сохраняется в той же транзакции и
отображается в лобби. Полная проверка совместимости и production OAuth validation
ещё не завершены.
