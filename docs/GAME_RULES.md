# Правила игры

Документ описывает правила, которые исполняют Rust `durak-engine` и HTTP backend `platform-api`. MCP использует тот же backend через SSE и не является отдельной реализацией правил.

## Стол и колода

- За столом от 2 до 6 мест. Игру начинает создатель комнаты, когда подключены минимум два игрока.
- Доступны колоды на 36 и 52 карты. В 36-карточной колоде достоинства `6, 7, 8, 9, 10, В, Д, К, Т`; в 52-карточной добавляются `2, 3, 4, 5`.
- Масти: `♠`, `♥`, `♦`, `♣`. Карта определяется достоинством и мастью.
- В начале раунда каждому игроку раздают по шесть карт. Козырь выбирается по `deck[0]`: эта карта остаётся в колоде и раздаётся последней. Когда колода заканчивается, масть козыря сохраняется, а видимая карта исчезает.
- Размер руки ограничен шестью картами при доборе. Игроки получают карты по кругу, начиная с атакующего текущего розыгрыша; защитник добирает последним.

## Старшинство и первый ход

- В одной масти карта бьёт карту только при большем достоинстве. Козырь бьёт любую некозырную карту; некозырь не бьёт козырь.
- Первым атакует игрок с младшим козырем среди розданных карт. Если козырей нет, выбирается игрок с младшей картой. При равенстве используется первый игрок в порядке мест.
- Первоначальный защитник — следующий активный игрок по кругу.

## Атака и подкидывание

- Игроки обходятся по порядку мест; игроки с пустой рукой после окончания колоды и покинувшие стол пропускаются.
- Пустой стол открывает только атакующий. После открытия подкидывать могут активные игроки, кроме защитника.
- Каждая новая карта должна иметь достоинство, которое уже есть среди атакующих или защитных карт на столе. Масть для права подкидывания не важна.
- На столе может быть не больше шести атакующих карт. Новая атака также запрещена, если у защитника карт не больше, чем непокрытых строк.
- Движок ведёт очередь подкидывания по кругу от атакующего; `pass` передаёт её следующему участнику. HTTP-слой также допускает подкидывание активным незащищающимся игроком, пока защитник отвечает на непокрытую карту, и корректирует очередь при взятии. Проверка действия сервером обязательна даже при наличии подсказки.
- После покрытия всех карт защитник не отбивается повторно: очередь подкидывания проходит по активным игрокам, затем `pass` завершает розыгрыш.
- После `take` защитник объявляет, что берёт карты, но розыгрыш не завершается немедленно. Остальные активные игроки могут подкинуть карты и последовательно передать очередь `pass`. После последнего `pass` стол переходит в руку защитника.

## Защита

- Защищаться может только текущий защитник. Защитная карта выбирается для указанной непокрытой строки; без `targetCardId` выбирается первая подходящая непокрытая строка.
- Защитная карта должна быть старше карты той же масти либо быть козырем против некозырной карты.
- Пока есть непокрытая строка, `pass` защитника запрещён. Защитник может использовать `take`, если на столе есть хотя бы одна непокрытая карта.
- После успешного отбоя карты стола переходят в сброс. После взятия все карты стола, включая уже покрытые пары, переходят в руку защитника.

## Переводной режим

- Комната работает в режиме `classic` или `transfer`. Перевод доступен только в `transfer`.
- Защитник может перевести ход, пока ни одна карта не покрыта, если все атакующие карты имеют одно достоинство и у защитника есть карта такого достоинства.
- Следующий защитник должен иметь не меньше карт, чем станет строк на столе после перевода. Перевод при заполненном столе, после покрытия, после `take` или без следующего активного игрока запрещён.
- После перевода текущий защитник становится атакующим, следующий активный игрок — защитником. Список спасовавших подкидывающих сбрасывается.

## Поворот ролей и завершение розыгрыша

- После отбоя или взятия сначала очищается стол и выполняется добор, затем выбираются роли следующего розыгрыша.
- После отбоя новым атакующим становится бывший защитник. После взятия атакующим становится следующий активный игрок после защитника.
- После каждого завершённого розыгрыша движок помечает игрока завершившим, только если колода пуста и его рука пуста.
- Партия заканчивается, когда активных игроков не больше одного. Последний активный игрок становится дураком; если активных игроков не осталось, результатом является ничья.

## Ставки и settlement

- Допустимые ставки: `0`, `50`, `100`, `250`, `500`; другие значения нормализуются к нулю. Начальный баланс аккаунта — 1000.
- Перед стартом каждый подключённый игрок должен иметь баланс не меньше ставки. При старте ставка списывается, а банк равен ставке, умноженной на число игроков.
- При обычном завершении проигравший теряет ставку, остальные делят банк; остаток распределяется по порядку игроков. При ничьей ставки возвращаются.
- Активный игрок, покинувший идущую партию, считается проигравшим. Отключение сохраняет место; если все участники остаются отключёнными пять минут, backend отменяет партию и возвращает ставки без истории и статистики. Завершённые комнаты хранятся ограниченное время.

## Снимки и инварианты

- В каждый момент карта находится ровно в колоде, руке игрока, сбросе, атаке на столе или защите на столе.
- Строка стола содержит одну карту атаки и не более одной карты защиты; покрытая строка не может быть покрыта повторно.
- При выборе следующего участника движок пропускает завершивших игру и покинувших стол игроков.
- Снимок HTTP для игрока содержит его карты и только размеры рук соперников. MCP сокращает снимок для ответа инструмента, а `verbose: true` добавляет полный JSON.
- Игровые переходы и изменения аккаунтов записываются backend в SQLite атомарно; активные комнаты восстанавливаются после перезапуска при успешной проверке идентичности игроков.

## HTTP и MCP

- Игровые действия backend принимает как `attack`, `defend`, `transfer`, `take`, `pass`; для действий с картой используются `cardId` и при необходимости `targetCardId`.
- Для игровых POST нужен действительный `clientId` и токен сессии, а открытый SSE-поток обязателен. MCP открывает места через `durak_connect`, после чего использует `durak_action`.
- `durak_wait` и `durak_watch` ожидают события через `/api/watch`; `durak_follow` сам выполняет легальные ходы до конца партии. MCP может предварительно рассчитывать подсказки, но backend остаётся источником истины.
