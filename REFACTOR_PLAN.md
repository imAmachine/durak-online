### Приоритетные дефекты, зафиксированные без исправлений

1. **Отмена стола и возврат ставок неатомарны.** `platform-api/src/game.rs:1209` сначала убирает комнату из памяти, затем раздельно сохраняет возвраты и удаляет снимок, игнорируя ошибки SQLite. Сбой между записями может оставить частичные возвраты или восстановить уже отменённую комнату. Отдельное исправление: один переход хранилища и тесты сбоев на каждом этапе.
2. **Правка аккаунта и отзыв сессии могут разойтись.** `platform-api/src/game.rs:1163` сначала сохраняет аккаунт, затем отдельно меняет пароль и закрывает сессию. Сбой второго шага оставляет запись уже обновлённой на диске, при этом API сообщает ошибку, а память хранит прежнее состояние. Отдельное исправление: атомарная запись аккаунта и отзыва с проверкой после перезапуска.
3. **JS MCP сообщает об успешном выходе при HTTP-отказе.** `mcp/server.mjs:951` игнорирует `ok` ответа и очищает локальное состояние. `mcp/server.mjs:403` может принять постороннее SSE-событие за подтверждение действия и вернуть старый снимок. Отдельное исправление: различать отказ HTTP, принятое действие без нового снимка и подтверждённое обновление.
4. **Ожидание следующего хода может обработать ошибку как нормальный ответ.** Rust MCP разбирает JSON до проверки статуса в `platform-mcp/src/main.rs:230`, в отличие от пути `follow` в `main.rs:407`. JS при SSE fallback проверяет обновление без автора даже для `until=opponent` (`mcp/server.mjs:465`). Просроченный ответ watch может перезаписать более новый снимок. Каждую семантику зафиксировать отдельно, поведенческие исправления отделить от объединения транспорта.
5. **Учёт виденных карт переносится в следующий раунд того же стола.** JS очищает стол и сброс, оставляя `seen` на `start` (`mcp/strategy.mjs:148`). В Rust аналогичная ветка в `platform-mcp/src/strategy.rs:289`. JS воспроизведён на данных в памяти. Для отдельного исправления пригодится общий сценарий рематча с новым набором видимых карт.
6. **Компактная раскладка активируется на четырёх парах.** `style.css:1602` считает `div#tableDropZone` из `index.html:122` при вычислении `nth-of-type(5)`. Наблюдаемую раскладку сохранить в рефакторинге. Если пять пар — нужный продуктовый порог, проверять его отдельным исправлением на четырёх и пяти парах.
7. **Интеграционный прогон может скрыть регрессию.** `tests/mcp-sessions.mjs:83` трактует любой неуспешный пробный запрос как пропуск, временный каталог убирается только на успешном пути (`tests/mcp-sessions.mjs:132`). `tests/mcp.mjs:117` подаёт одинаковую готовую клубную пару логин/пароль на оба места.
